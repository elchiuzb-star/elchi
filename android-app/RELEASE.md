# Android release — signing and versioning

## ⚠️ The signing key

The upload keystore is at `credentials/elchi-release.keystore`, which is
**gitignored**. It is not in the repository and cannot be recovered from it.

```
alias   elchi
SHA-1   CD:8F:7F:BE:54:06:CE:77:FB:9C:21:21:F7:42:FF:ED:B2:C5:5D:AC
SHA-256 CE:8C:C7:AF:4F:87:CF:DF:C1:B5:7B:A4:C7:FB:BC:18:06:5C:62:78:42:65:2C:1C:1F:F6:D8:40:06:D3:28:0F
valid   2026-07-14 → 2053-11-29
```

**Why it moved.** It used to live only in `android/app/`. That whole directory
is gitignored *and* regenerated by `expo prebuild`, so a single
`expo prebuild --clean` would have destroyed it. Once an app is published,
Play refuses any upload signed with a different key — losing it means never
being able to update the app again.

**Back it up now**, outside this machine: a password manager entry or encrypted
storage holding the `.keystore` file plus its store and key passwords.

**Enrol in Play App Signing** when you first upload. Google then holds the real
app signing key and yours becomes only an *upload* key — which Google can reset
if you lose it. That turns an unrecoverable failure into a support ticket.

### Restoring after a clean prebuild

`expo prebuild --clean` wipes `android/`, including the copy Gradle reads and
the credentials block in `android/gradle.properties`. To restore:

```bash
cp credentials/elchi-release.keystore android/app/elchi-release.keystore
cat >> android/gradle.properties <<'EOF'
ELCHI_RELEASE_STORE_FILE=elchi-release.keystore
ELCHI_RELEASE_KEY_ALIAS=elchi
ELCHI_RELEASE_STORE_PASSWORD=<from your password manager>
ELCHI_RELEASE_KEY_PASSWORD=<from your password manager>
EOF
```

> The password currently committed to `android/gradle.properties` history is
> weak (`elchi123456`). Since nothing has been published yet, this is the last
> painless moment to generate a stronger keystore. After the first release it
> can only be changed by enrolling in Play App Signing and requesting a key
> reset.

## Versioning

`versionCode` and `versionName` live in `app.json`, not `android/app/build.gradle`
— the latter is regenerated by prebuild and any edit there is lost.

```jsonc
"version": "1.0.0",        // versionName, shown to users
"android": { "versionCode": 1 }
```

Play requires a **strictly higher `versionCode` for every upload**, even for a
re-upload of the same release. Bump it before each build.

## Building a release AAB

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"

cd android && ./gradlew bundleRelease
# → android/app/build/outputs/bundle/release/app-release.aab
```

Verify what you are about to upload:

```bash
"$JAVA_HOME/bin/keytool" -printcert -jarfile \
  android/app/build/outputs/bundle/release/app-release.aab
```

The SHA-256 must match the fingerprint above. If it does not, Gradle fell back
to the debug key and Play will reject the upload.
