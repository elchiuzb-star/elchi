# Tables with a trigger whose non-SECURITY-DEFINER function reads a session setting or pg_trigger_depth()
# (scripts/db_roles.py GUARDED_TABLES_SQL). scripts/deploy.sh fails when the detected set differs from the
# table names below (wave 1.7 NEW-5). Change this file together with the migration that adds/removes a guard.
#
# Format: <table> [read-only|app-marker]   (class defaults to read-only; a detected table missing here is read-only)
#   read-only  -- the guard trusts session state that any session could set, and the only legitimate writer is
#                 a SECURITY DEFINER trigger: db_roles.py revokes INSERT/UPDATE/DELETE/TRUNCATE from the app role.
#   app-marker -- the setting is a transaction marker the APPLICATION sets (or evidence re-checked against real
#                 rows); the app role is the legitimate writer and keeps DML. Grant review: these guards stop
#                 accidental psql/migration writes, not a deliberate actor with app-role credentials
#                 (Q36 roles, history/audit rows and monitoring cover that).
ledger_account_balances read-only   # 0047: balance writer is the SECURITY DEFINER ledger_entries trigger (Q48)
bookings                app-marker  # 0056 Q60: amount columns change only if the accepted-amendment marker names a real accepted amendment with matching values
booking_amendments      app-marker  # 0056 Q60: AFTER UPDATE trigger that appends the accepted amendment id to the marker (writer, not a guard)
feature_flag_values     app-marker  # 0057 Q72: enabling a v2 flag needs the admin-API marker set by geo.service.set_flag_value (0084 adds the same marker check for promotions_enabled)
promo_budgets           read-only   # 0084 Q115: budget cache writer is the SECURITY DEFINER promo_ledger_transactions trigger
